# Avledet под Valheim 1.0.20

Цель: легкий C++ сервер (Avledet, ~100 MB RAM) для ванильных клиентов 1.0.20 без модов.

Основа: `crazicrafter1/Avledet`, ветка `0.221.12-replay-B-semi-atomic-modular` (не стабильная `0.221.12`): только её читатели `.pkg` совпадают с форматом выгрузчика AvlIntrinsics. Расхождение со стабильной около 4100 строк, сетевой код почти тот же. Replay в ней не включать. Старая версия совпадает с Steam-веткой `default_pre1_0`, поэтому дифф декомпиляций 0.221.12 и 1.0.20 и есть объем порта. Детали в `re/notes/{net,zdo,world}.md`. Каталог `re/` в git не идет: там декомпилированный код, EULA §5.2.5.

## Что ломается сейчас

Клиент 1.0 отваливается уже на `ServerHandshake`. Вызов получил строковый аргумент, а `Method.h` в Avledet бросает исключение на лишних байтах. Это происходит еще до проверки версии.

## Изменения

Сеть (~80 строк минимум, ~150 с желательными):
- `VConstants::NETWORK` = 41. Проверять только network, а не строку версии игры, иначе каждый хотфикс ломает сервер.
- `ServerHandshake`: принять строку (invite secret key).
- PeerInfo клиент -> сервер, новый порядок: uid, version, network, pos, name, playfabId, simDistance(int near, int far, bool classic), password, inviteSecretKey, ticket.
- PeerInfo сервер -> клиент: после name пустой playfabId и simDistance (2,2,true).
- Отправлять `RPC_ValidatedSimulationDistance` (2,2,true) до PeerInfo, обрабатывать `RPC_RequestValidSimulationDistance`.
- `PlayerList`: playfabId после имени. ID игрока `Steam_<id>`, а не `steam_`. Списки admin/ban принимают `Steam_<id>` и `V_<id>`.
- Желательно: `Ping`/`Pong` переименованы в `RPC_Ping`/`RPC_Pong`, пустой `HistoricalPlayerList`, `{"list":[]}` на `RequestActiveEventsList`.

ZDO (~60-120 строк):
- `ZDO::_read_num_items`: в сетевом пути читать varint (1 байт до 128, иначе 2).
- Остальной wire-формат (ZDOID, ZDOData, флаги, ревизии, Destroy/Request) не менялся.

Мир (~800-900 строк), обязателен, потому что только сервер наполняет зоны:
- Высота Deep North: новая формула, без перехода в Mountain выше 0.4, реки в два прохода.
- Попытки размещения локаций (60000/12000, 6 точек на зону), enum `GlobalKey`.
- `discoverAll` в запросе поиска локаций, пустой ответ на persistent events.
- Радиус генерации по simulation distance.
- Сетка биомов 2048x2048 и альтернативные биомы (~500 строк). Обязательно: клиент считает их сам, и без совпадения растительность не ляжет на рельеф. Итого по миру ~800-900 строк.

Данные `.pkg`: выгрузчик готов (см. ниже), осталось расширить формат и читатели.

Сохранение мира только в формате 1.0 (чанковое, версия 42), в той же папке, что у ванили: сервер меняется на месте в обе стороны. Старые `.fwl/.db` и миры 0.221 не поддерживаются.

## Проверено на реальных бинарниках

- Клиент 1.0.20 (из локальной установки) без `RPC_ValidatedSimulationDistance` остается с simulation distance (0,0) и не грузит зоны. RPC обязателен.
- Альтернативные биомы детерминированы по seed (по IL: `Utils::Shuffle` на UnityEngine.Random). Клиент сам считает сетку биомов при подключении и использует alt-биомы в Heightmap, поэтому сервер обязан воспроизводить их точно. Это переносит сетку 2048x2048 и alt-биомы из «позже» в обязательную часть генерации мира.
- Steam-слой не менялся с 0.221.12: `SteamGameServer015`, `SteamNetworkingSockets012`.
- Реальное сохранение 1.0.20 совпадает с разобранным форматом (`re/notes/zdo.md`).
- Ванильный сервер 1.0.20 без игроков: ~1.3 GB RAM, генерация мира 17 с.

## Риск

Клиенты без модов подключаются через Steam networking, значит единственный путь это `steam_dedicated` acceptor. Автор ServerAuthority бросил его как нестабильный (`SteamGameServer_InitEx`), в апстриме есть ветки `steam-server-fix*`. Проверить его первым делом.

Цель 1 в 1 с ванилью (27.10, второй заход). Ваниль сама по себе не повторяется: поворот локаций берется из несидированного `UnityEngine.Random`. В Avledet он сидирован как у локации, ванильный зонд делает то же при `PROBE_SEEDED_ROTATION=1` (эталон `re/probe-zones-*` снят так). Итог: рельеф, биомы, локации 100%; части локаций 100% ванильных на месте (176 из 181 локации без расхождений, остаток это объекты, которые живут сами: рост лоз, вороны, обломки с таймером); сиды всех 20 данжей совпадают; растительность 49.6% по точкам.

Исправлено во втором заходе:
- Паинт-маска 65x65 с шагом 65 и 8 бит на канал, как текстура RGBA32 в ванили (у Avledet была 64x64 со сдвигом строк).
- Шаги `UnityEngine.Random` в `Awake` при `Instantiate` (замерены выгрузчиком в `awake.json` для 529 префабов): растительность, двери, части локаций и комнат. Случайное здоровье руин (`m_applyRandomDamage`, `WearNTear`) пишется в ZDO.
- `Quaternion.eulerAngles` и `Quaternion.Euler` перенесены из `UnityPlayer.so` бит в бит (20000/20000). ZDO хранит поворот углами, и клиент видел наклоненные объекты повернутыми иначе. Сборка с `-ffp-contract=off`.
- `LocalToGlobal` умножал повороты в обратном порядке. Алгоритм `Dungeon` теперь считает в мировых координатах, как ваниль.
- Позиция генератора интерьера через ту же цепочку float, что в ванили; сид комнат по флагу генератора `m_useCustomInteriorTransform`.
- `RandomObject` сравнивает записи по объекту; списки собираются до `RandomSpawn.Reset` в выгрузчике.
- Ванильные причуды повторены: `m_OffObject`, который выключен в префабе, получает ZDO при спавне визуала локации или комнаты; вложенные сетевые части создаются второй раз вместе с родителем.
- Самодельная проверка по радиусу у растительности только там, где ваниль делает `IsBlocked`.

Третий заход (27.10): `TerrainModifier` локаций и `SnapToGround`, затем физика растительности. Эталон `re/probe-phys-<seed>` снят с `PROBE_PHYS=1`: ваниль пишет каждый `IsBlocked` и `GetStaticSolidHeight` в `phys.txt`, Avledet пишет то же (`AVL_PROBE_PHYS`), `tools/compare_phys.py` ищет первое расхождение в каждой зоне. Итог: объекты зон 100.0% (43002 из 43019), растительность 99.9% (с режимом изоляции зонда, см. ниже), рейкасты совпадают целиком в 167 из 207 зон.

Исправлено в третьем заходе:
- `Physics.cpp`: коллайдеры зоны (box, sphere, capsule, mesh, convex) из `colliders.pkg` и списков в `vegetation.pkg`/`features.pkg`/`dungeons.pkg`, луч вниз по сетке 1 м. `IsBlocked` и `m_snapToStaticSolid` вместо самодельной проверки по радиусу. Сетка 260 м: при `groupRadius` больше 32 (Ashlands, до 80) кандидаты уходят до ~128 м от центра зоны.
- Угловые биомы карты высот (`HaveBiome`, `Heightmap.GetBiome`) берутся из сетки секторов (`GetBiomeSector`), высоты по-прежнему смешиваются по `GetBiome`. Раньше в зонах на границе биомов не запускалась растительность соседнего биома.
- Выгрузчик: сид растительности считается от полного имени GameObject (`SnowFirTree 2`), а не от `GetPrefabName`; ZDO получает обрезанное имя, как в ванили.
- Выгрузчик: `m_clearArea` берется из `ZoneLocation`, а не из компонента `Location` (у 18 локаций флаги разные, например `CombatRuin01`, `StoneTowerRuins*_sunk`, `SulfurArch`).
- Выгрузчик: коллайдеры растительности, выключенные в префабе, пишутся вторым списком. Ваниль после `SetLocalScale` делает `enabled = false; enabled = true` для всех коллайдеров активных объектов и этим включает их (convex `stub` у `AshlandsBush1`). Avledet добавляет их, если масштаб отличается от префаба.
- Режим зонда `AVL_PROBE_ZONES`: зона генерируется одна, рельефа соседних зон нет (кандидат вне зоны отбрасывается, выборки `GetTerrainDelta` вне зоны дают высоту центра). Так работает ванильный зонд. В живой ванили итог для кандидатов за границей зоны зависит от порядка загрузки зон (`CreateLocalZones` сначала генерирует зону игрока, потом соседей), канонического ответа нет; Avledet вне зонда всегда видит рельеф соседей.

Четвертый заход (27.10): нативная математика трансформов Unity (`UnityTransform.cpp`, порт из `UnityPlayer.so` инструкция в инструкцию, тест `UnityTransformTest` на 40000 иерархиях из игры): нормализация поворота в сеттере, мировые позы детей, world -> local для комнат под генератором. Отсюда совпал последний данж (`Hildir_crypt`: сид концевой комнаты зависел от позиции с погрешностью 0.0005). Объекты, которые ваниль удаляет сама (`Gibber`, `TimedDestruction` на Awake), живут свое время (`lifetimes.json`); части под `ConditionalObject` не создаются, пока ключ не выполнен. Сравнение зон: непостоянные объекты не учитываются (ванильный зонд держит точку отсчета далеко, они у него исчезают сразу), объекты в одной точке сопоставляются с учетом поворота (раньше пары путались). Итог: 201 из 207 зон без единого расхождения, локации 180/181.

Важно: `rcpps` в world -> local дает разные биты на разных моделях CPU, поэтому сама ваниль на Intel и AMD генерирует чуть разное. Avledet использует те же инструкции и совпадает с ванилью на том же процессоре.

Пятый заход (27.10): эталон переснят в режиме Ghost (`re/probe-ghost-<seed>`, `PROBE_GHOST=1`), как работает живой выделенный сервер: зона создается и сразу уничтожается, без `Start`/`Update`/физики, визуалы локаций и их `TerrainModifier` не ставятся. Падение `BogWitch` и обрушение доски `ShipWreck04` были артефактами старого эталона в режиме Full. Итог: 203 из 207 зон без расхождений, локации 181/181, объекты 43004 из 43019.

Шестой заход (27.10), сверка бит в бит. Сравнения зон шли с допуском и прятали расхождения в последнем бите у трети объектов. Теперь `tools/compare_bits.py` (в конце `avl-probe.sh`) сравнивает объекты по битам float, пара по ближайшей точке, иначе стопки одинаковых блоков путаются; бот считает `not bit exact` по позиции и повороту. Поиск нативной функции за icall Mono в `UnityPlayer.so`: `tools/unity-icall.py`. Найдено и исправлено:
- Mono в игре считает float-выражения C# в double и округляет при записи в переменную или поле. Так теперь работают `Quaternion * Vector3`, `Quaternion * Quaternion`, `Dot`, `SqrMagnitude`, `magnitude`, `Distance`, `normalized` и `Vector3.Cross` у наклона растительности. Проверено на 20000 случаях из игры (`managed_test.json`). Из-за `Vector2.SqrMagnitude` в `GetWeight` вес реки расходился на 1-2 ULP в 4% вершин карты высот, отсюда высота растительности.
- Высота и нормаль земли по шагам PhysX BV4 (`RayTriOverlapT`, точка `p1*u + p2*v + p0*w`, нормаль через обратную длину), а не интерполяцией плоскости.
- `Quaternion.LookRotation` перенесен из `UnityPlayer.so` (20000 из 20000, `look_test.json`).
- `m_slopeRotation`: `eulerAngles.y` в [0, 360) и `Mathf.Round` с округлением половины к четному. Раньше `atan2` давал -180 вместо 180, другие биты у всех частей локации.
- `HistoricalPlayerList` новому игроку уходит дважды, как в ванили. Модификаторы рельефа зоны снимаются после ее генерации.

Выгрузчик: `AVL_DUMP_TESTS=1` пишет только тесты математики (`transform*`, `look_test`, `managed_test`) за минуту; `AVL_TRANSFORM_TESTS=re/pkg-1.0.20/json` для `avledet_util_test`. Ванильный зонд: `PROBE_GROUND=1` вместе с `PROBE_PHYS=1` пишет треугольник и вершины меша под каждым лучом к земле. **Сохранения 1.0 (27.10). ГОТОВО.** Avledet читает и пишет ванильный мир в `<savedir>/worlds_local/<мир>/` (ключ `world.savedir` в `server.yml`, как `-savedir` у ванили): `_main.N.fwl2` (мета, стартовые ключи, история игроков), `.db2` (время, зоны и локации в gzip, случайное событие, persistent events как есть), `.chunks` и файлы `.chunk` по 8x8 зон, порталы отдельным чанком. Сохранение пишет набор N+1 целиком, затем удаляет N и чанки, которых нет в новом индексе. Связи ZDO (порталы, спавнеры, sync transform) сохраняются хешами пар и восстанавливаются при загрузке, раньше этого не было вовсе. ZDO с префабом, неизвестным серверу, при загрузке отбрасываются с предупреждением (у ванильного мира 1.0.20 таких нет).
